# 08｜代码与资源命名规范

**状态：强制执行**  
**版本：1.0**

本规范保证开发者 A、开发者 B 和负责人 C 使用 Codex 并行工作时，对同一业务实体使用同一个名称。

## 1. 命名总原则

1. 代码名称以英文业务概念为准，用户界面文案以 `docs/07` 固定中文为准。
2. 一个概念只有一个正式名称，不创建缩写和同义字段。
3. 名称表达业务含义，不表达暂时的页面位置或实现细节。
4. 布尔值使用肯定语义，如 `isPublished`，避免 `notDisabled`。
5. 集合使用复数，单个对象使用单数。
6. 状态和角色使用受控枚举，不在代码中散落任意字符串。

## 3. 目录与文件

### 3.1 目录

- 应用、package、feature：`kebab-case`。
- Expo Router 路由组：使用稳定角色代码，例如 `(teacher)`、`(family)`。
- 测试目录固定为 `__tests__`，不混用 `tests`、`spec`。

```text
apps/client/src/features/student-score/
apps/client/src/features/class-score/
apps/client/src/features/dolphin-bank/
apps/client/src/features/ai-center/
```

### 3.2 TypeScript 文件

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| React 组件 | `PascalCase.tsx` | `StudentScoreCard.tsx` |
| Hook | `useXxx.ts` | `useStudentRanking.ts` |
| Service | `xxxService.ts` | `coursewareService.ts` |
| Schema | `xxxSchema.ts` | `fineOrderSchema.ts` |
| 类型 | `xxx.types.ts` | `studentScore.types.ts` |
| 常量 | `xxx.constants.ts` | `operation.constants.ts` |
| 测试 | 与目标同名 `.test.ts(x)` | `StudentScoreCard.test.tsx` |
| Story／fixture | `xxx.fixture.ts` | `studentScore.fixture.ts` |

每个 feature 的公共入口使用 `index.ts`，只导出稳定公共 API，不使用多层 barrel 导出造成循环依赖。

## 4. TypeScript 标识符

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 变量、函数 | `camelCase` | `studentScoreTotal` |
| React 组件、类型 | `PascalCase` | `StudentScoreEntry` |
| 常量对象 | `SCREAMING_SNAKE_CASE` | `MAX_FINE_AMOUNT` |
| 枚举替代 | `as const` 对象 + 类型 | `OPERATION_STATUS` |
| 布尔值 | `is/has/can/should` | `canReverse` |
| 事件回调 | `handleXxx` | `handlePublish` |
| Props 回调 | `onXxx` | `onPublish` |
| 异步读取 | `get/list/find` | `listCourseware` |
| 写操作 | 明确动词 | `publishAssignment`, `reverseOperation` |

禁止：

- 无意义变量：`data1`、`temp`、`obj`、`info`。
- 单字母业务变量，循环索引除外。
- 以页面命名领域类型，例如 `TeacherPageData`；应命名为实际 DTO。
- 使用 `IStudent`、`TStudent` 前缀；直接使用 `Student`。

## 5. React 组件命名

组件名称采用“领域 + 组件职责”：

```text
CoursewareList

AssignmentPublishDialog
GradeRevisionHistory
StudentScoreEntryCard
ClassRankingTable
DolphinAccountBalance
FineOrderConfirmCard
OperationReversalDialog

```

页面组件以 `Screen` 结尾，路由文件保持薄层：

```text
TeacherHomeScreen

```

通用组件禁止携带领域名，例如使用 `ConfirmDialog`；只有业务确认组件使用 `OperationReversalDialog`。

## 6. 路由命名

URL 和 Expo 路由使用小写 `kebab-case`，资源名优先复数：

```text
/(teacher)/courseware
/(teacher)/assignments
/(teacher)/classes/[classId]/student-scores
/(class-terminal)/class-performance
/(family)/students/[studentId]/grades
/(bank-operator)/dolphin-accounts/[accountId]
/(council)/classes/[classId]/class-scores
/(admin)/operation-audit
```

路由参数使用 `camelCase`：`studentId`、`classId`、`operationId`。数据库字段仍使用 `snake_case`，由 DTO 映射层转换。

## 7. API 命名

- REST 资源使用小写复数和连字符。
- 查询使用 `GET`，创建使用 `POST`，完整替换使用 `PUT`，部分修改使用 `PATCH`。
- 复杂业务动作使用资源后的明确动作词，不伪装为字段修改。

```text
GET  /classes/{class_id}/student-ranking
POST /student-scores
POST /assignments/{id}/publish
POST /operations/{id}/reversal-preview
POST /operations/{id}/reverse
POST /ai/action-drafts/{id}/confirm
```

### DTO

```text
CreateStudentScoreRequest
StudentScoreEntryResponse
StudentRankingResponse
CreateFineOrderRequest
OperationReversalPreviewResponse
```

请求和响应在网络层使用 `snake_case`；映射后的应用模型使用 `camelCase`。映射必须集中，不允许页面临时转换。

## 8. 数据库命名

### 8.1 表与字段

- PostgreSQL 表：复数 `snake_case`。
- 主键统一为 `id`。
- 外键统一为 `<entity>_id`。
- 时间统一为 `<verb>_at`，类型为 `timestamptz`。
- 布尔字段使用 `is_`、`has_`、`can_`。
- 计数使用 `_count`，整数变化量使用 `delta`。

正确示例：

```text
student_score_entries
class_score_entries
dolphin_accounts
dolphin_transactions
fine_orders
operations
reversal_links
ai_action_drafts
```

禁止创建：

```text
student_points
class_points
coin_logs
undo_records
student_score_and_grade
```

### 8.2 约束与索引

```text
pk_<table>
fk_<table>__<column>
uq_<table>__<columns>
ck_<table>__<rule>
idx_<table>__<columns>
```

示例：

```text
uq_operations__idempotency_key
ck_dolphin_accounts__balance_nonnegative
idx_student_score_entries__class_id_created_at
```

### 8.3 数据库函数

使用动词开头的 `snake_case`：

```text
create_student_score_entry
create_dolphin_transaction
preview_operation_reversal
reverse_operation
```

RLS policy 名称固定为：

```text
<table>__<action>__<role_or_rule>
```

示例：`grades__select__linked_family`。

## 9. 固定状态代码

用户显示文字来自 `docs/07`，代码只使用以下白名单。

### 内容发布

```text
draft | published | withdrawn | expired
```

### 作业家庭状态

```text
unacknowledged | acknowledged | completed
```

### 罚款单

```text
pending | processed | rejected | reversed
```

### 关键操作

```text
pending | succeeded | failed | reversed
```

### AI 写操作草稿

```text
pending | confirmed | cancelled | expired
```

禁止使用 `done`、`ok`、`normal`、`deleted` 等模糊状态。

## 10. 操作类型

操作类型使用 `<domain>.<verb>`：

```text
courseware.send
courseware.withdraw
assignment.publish
grade.publish
grade.revise
student_score.add
student_score.deduct
class_score.add
class_score.deduct
dolphin_coin.grant
dolphin_coin.deduct
fine_order.create
operation.reverse
operation.restore
```

同一业务动作不得出现 `student_score.increase` 与 `student_score.add` 两套写法。

## 11. 错误码

错误码使用大写 `SCREAMING_SNAKE_CASE`，对用户的中文提示由客户端映射：

```text
UNAUTHENTICATED
FORBIDDEN
NOT_FOUND
VALIDATION_ERROR
CONFLICT
DUPLICATE_REQUEST
INSUFFICIENT_BALANCE
ALREADY_REVERSED
ACTION_DRAFT_EXPIRED
AI_UNAVAILABLE
INTERNAL_ERROR
```

不得把数据库错误原文、堆栈或 DeepSeek 返回文本直接显示给用户。

## 12. TanStack Query 键

如果使用 TanStack Query，统一由 query key factory 生成：

```ts
studentScoreKeys.all
studentScoreKeys.byStudent(studentId)
studentScoreKeys.ranking(classId, period)
dolphinAccountKeys.detail(studentId)
operationKeys.list(filters)
```

禁止在页面中散落 `['score', id]`、`['student-score', id]` 等不一致数组。

## 13. 表单与 Schema

Zod Schema 命名：

```text
createStudentScoreSchema
publishAssignmentSchema
createFineOrderSchema
reverseOperationSchema
```

从 Schema 推导输入类型，不重复手写：

```ts
type CreateFineOrderInput = z.infer<typeof createFineOrderSchema>;
```

表单字段名称应对应应用模型 `camelCase`，提交时由 API mapper 转成 `snake_case`。

## 14. 测试命名

测试描述使用“场景 + 行为 + 结果”，可以中文书写：

```ts
describe('reverseOperation', () => {
  it('余额流水已撤销时再次请求应返回 ALREADY_REVERSED', () => {});
});
```

文件：

```text
reverseOperation.test.ts
StudentRankingTable.test.tsx
fine-order.rls.test.sql
```

测试账号固定前缀：

```text
demo_teacher_
demo_student_
demo_family_
demo_bank_
demo_council_
demo_admin_
```

不得在 fixture 中使用真实姓名、学号、电话或成绩。

## 15. 环境变量

客户端公开变量：

```text
EXPO_PUBLIC_SUPABASE_URL
EXPO_PUBLIC_SUPABASE_ANON_KEY
EXPO_PUBLIC_APP_ENV
```

服务端变量：

```text
SUPABASE_SERVICE_ROLE_KEY
COZE_API_BASE_URL
COZE_BOT_ID
COZE_API_TOKEN
COZE_SKILL_SHARED_SECRET
AI_CONTEXT_SIGNING_SECRET
```

规则：

- 所有环境变量使用大写 `SCREAMING_SNAKE_CASE`。
- 只有确实可公开的变量使用 `EXPO_PUBLIC_`。
- `.env.example` 只写变量名和假值，不写真实密钥。
- 测试和日志只检查“是否设置”，不输出值。

资源文件使用小写 `kebab-case`，包含语义和状态，不包含中文、空格或版本号 `final2`。

## 19. 新名称引入流程

当 Issue 需要本文档没有的新实体、状态或动作：

1. 搜索仓库确认没有现有同义词。
2. 在 Issue 提出中文名称、英文代码名和使用范围。
3. 更新 `docs/07` 或 `docs/08`。
4. 涉及跨模块或不可逆数据变化时创建 ADR。
5. 规范 PR 合并后再实现业务。

Codex 不得因为某个名称“听起来更自然”就自行改名。

## 20. Review 清单

- [ ] 没有为现有业务创建第二个英文名称。
- [ ] 目录、组件、Hook、Schema 和测试文件符合格式。
- [ ] API 和数据库字段在映射层清晰转换。
- [ ] 状态来自白名单，中文文案来自固定映射。
- [ ] 错误码稳定，不依赖自然语言判断。
- [ ] 数据库约束、索引和 RLS policy 命名一致。
- [ ] 资源没有中文、空格、`new`、`final`、`v2-final`。
- [ ] 没有硬编码 DeepSeek 密钥或真实数据。
