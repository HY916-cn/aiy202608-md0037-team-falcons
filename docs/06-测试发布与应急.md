# 06｜测试、发布与应急

## 1. 质量目标

MVP 的首要目标不是功能数量，而是演示路径稳定、权限正确、账务可追溯、DeepSeek 故障可降级。

发布门槛：

- P0、P1 缺陷为 0。
- 核心演示场景全部通过。
- 四端构建和安装证据齐全。
- 数据库从空库迁移成功，种子数据可重复加载。
- 构建物能追溯到 tag 和 commit SHA。

## 2. 测试分层

### 2.1 静态检查

- ESLint。
- TypeScript strict typecheck。
- 格式检查。
- 依赖和 secret scan。
- 数据库迁移命名与危险语句检查。

### 2.2 单元测试

重点：

- 排行周期、并列名次和排序稳定性。
- 权限辅助函数和角色切换。
- API DTO 映射、输入 Schema 和错误码映射。
- 撤销影响计算和反向 delta。
- 罚款状态机、余额不足和上限校验。
- 今日摘要的事实聚合。

### 2.3 数据库与 RLS 测试

至少覆盖：

- 教师不能操作未授课班级。
- 班级端不能读取个人成绩、余额和罚款。
- 家庭只能读取绑定学生。
- 自治会只能修改授权范围班级分。
- 教师不能直接修改海豚币余额。
- 余额更新与流水写入原子完成。
- 重复幂等键只产生一个结果。
- 两个并发撤销只有一个成功。
- 已合并迁移能从空库完整执行。

### 2.4 组件与页面测试

- 加载、空数据、错误、无权限和成功状态。
- 写操作确认卡显示对象、数值和原因。
- 公共班级端的隐私隐藏。
- Web 和原生端的文件选择、下载反馈差异。
- 吉祥物状态不遮挡主要操作。

### 2.5 端到端／手工路径

黑客松阶段优先维护少量稳定路径：

1. 教师登录 → 发课件 → 班级端下载。
2. 班级授权操作者加学生分 → 排行变化 → 家庭查看本人。
3. 自治会加班级分 → 教师查看。
4. 教师发作业和成绩 → 家庭查看。
5. 教师发起罚款 → 银行流水 → 家庭查看。
6. 银行指定撤销 → 余额恢复 → 审计存在。
7. AI 查询 → AI 写草稿 → 用户确认 → 仅执行一次。
8. 禁用 DeepSeek → 普通页面继续完成核心业务。

## 3. 测试数据

只使用合成数据，固定种子应包含：

- 1 所学校、2 个年级、3 个班级。
- 教师 2 名，其中一人教授两个班。
- 每班至少 8 名学生，用于并列排行。
- 家庭账号 3 个，其中一个绑定两个孩子。
- 班级公共设备账号 2 个和授权操作者。
- 银行账号、自治会账号、管理员各 1 个。
- 学生分、班级分、海豚币、罚款、作业和成绩的正常及边界数据。
- 已撤销操作、余额不足罚款和过期 AI 草稿。

种子脚本应可重复执行并得到相同演示身份，不包含真实姓名、学号、成绩或联系方式。

## 4. PR 测试矩阵

| 变更类型 | 必需检查 |
| --- | --- |
| 纯 UI | lint、typecheck、组件测试、目标 Web + 一种原生端截图 |
| 普通业务 | 上述检查 + 单元测试 + 角色路径 |
| 权限／RLS | 数据库测试 + 正反角色用例 |
| 分数／币账／撤销 | 数据库事务、幂等、并发、回归路径 |
| 文件 | 上传类型、大小、私有下载、撤回与错误网络 |
| DeepSeek 接入 | 超时、无效结构、越权、草稿过期、重复确认、降级 |
| 构建配置 | 对应平台干净构建和安装／启动 |

## 5. CI 阶段

推荐 pipeline：

```text
checkout
→ pnpm install --frozen-lockfile
→ secret scan
→ lint + format check
→ typecheck
→ unit tests
→ Supabase migration + RLS tests
→ Expo Web export
→ 上传测试报告
```

规则：

- 固定 Node、pnpm 和 Java 版本。
- 使用依赖缓存但不得绕过 lockfile。
- CI 使用合成环境变量和隔离数据库。
- 日志不得输出服务角色密钥和 DeepSeek token。
- 失败检查不得由管理员手工标绿。

## 6. C 的 Review 与 QA 流程

### 代码审查

1. 阅读 Issue、产品边界和 PR 自检。
2. 先找 P0/P1：权限、账务、数据丢失、密钥、迁移和并发。
3. 检查测试是否真的覆盖失败条件。
4. 检查变更是否影响 DeepSeek 关闭时的普通功能。
5. 检查 UI 的目标角色和跨端差异。

### 拉取验证

```bash
git fetch origin pull/<PR_NUMBER>/head:review/pr-<PR_NUMBER>
git switch review/pr-<PR_NUMBER>
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
```

数据库、Web、Android、iOS 或 Electron 的具体命令以仓库 scripts 为准。C 在 PR 中记录实际执行命令和 commit SHA。

### 缺陷修复

- 业务局部问题：退回 A/B，并提供最小复现。
- 测试、CI、构建或跨模块问题：C 建独立 Issue 和 `fix/*` 分支。
- C 的修复 PR 由 A 或 B Review。
- 修复必须先添加或明确回归测试，避免只改到“当前演示能过”。

## 7. 四端构建

### Web

- 从干净 tag 安装依赖并导出生产 Web。
- 检查直接访问与刷新深层路由。
- 检查公开 bundle 不含 DeepSeek token、服务角色密钥和 source map 隐私。
- 在目标浏览器完成主演示路径。

### Android APK

- 使用固定 Expo/EAS 配置生成可直接安装 APK。
- 在至少一台真实 Android 设备安装、升级和冷启动。
- 验证文件选择、下载、会话恢复和 AI 降级。
- 记录 APK SHA-256。

### iOS 本地测试

- 只承诺模拟器或已配置设备本地测试。
- 记录 Xcode、iOS、设备和签名环境。
- 验证登录、家庭端查看、文件打开和角色切换。
- 不把 TestFlight 或 App Store 上架列为 MVP 完成条件。

### Windows EXE

- Electron 只加载受信任的本地 Expo Web 资源或明确生产域名。
- 启用 `contextIsolation`，关闭 `nodeIntegration`，限制外部导航。
- 在干净 Windows 环境安装或运行。
- 验证班级端课件接收、下载目录和更新失败提示。
- 记录 EXE 或安装包 SHA-256。

## 10. 演示应急

### DeepSeek 故障

- 切换到普通页面完成同一操作。
- 展示“AI 暂不可用，核心功能不受影响”。
- 必要时播放 AI 路径备用录屏。

### 网络故障

- 保留本地演示视频、界面截图和静态项目介绍。
- 不承诺离线写入；明确当前数据需要后端连接。

### 后端数据污染

- 演示前导出或保存可重复的合成种子。
- 使用预演脚本重置演示环境，不手工逐条修数据。
- 重置操作必须明确目标环境，禁止对未知环境执行。

### 构建物失败

- Web 为最低保底演示端。
- 保留上一份已验收 RC 构建物，不在现场只持有最新未测版本。
- 新 RC 失败时回退到上一 tag，不从开发者本地临时目录拼包。

## 11. 发布后记录

C 在 GitHub Release 中记录：

- 版本和 commit SHA。
- 四端构建状态和校验值。
- 数据库迁移版本。
- 演示账号说明的安全存放位置，不写密码。
- 已知问题和绕过方式。
- DeepSeek 服务是否启用及降级状态。
