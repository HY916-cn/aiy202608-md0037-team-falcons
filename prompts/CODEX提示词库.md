# Codex 提示词库

本文件供开发者 A、开发者 B 和质量构建负责人 C 使用。复制提示词时替换 `<...>` 占位符，并附上 GitHub Issue 链接或完整内容。

## 0. 使用规则

每次 Codex 会话只处理一个 Issue。提示词必须至少包含：

- 当前身份：A、B 或 C。
- 当前分支和 Issue。
- 目标结果与验收标准。
- 允许修改和禁止修改的路径。
- 必须运行的验证。
- 是否允许 commit、push、创建 PR、tag 或构建。

默认不授权 Codex commit、push、merge、tag、发布和外部部署。`START_HERE.md` 的实时协作提示词是例外：它明确授权当前 Issue 功能分支的 checkpoint commit、push 和 Draft PR，但不授权 main、force push、merge、tag、发布或部署。

任何提示词都继承以下硬规则：

```text
先完整阅读仓库根目录 AGENTS.md 和 Issue 引用文档。
涉及页面、业务、接口或数据时，必须阅读 docs/07-产品语言与视觉规范.md 和 docs/08-代码与资源命名规范.md；禁止自行创建同义名称、状态、图标或颜色。
开发过程不得调用 Coze、Coze CLI 或外部代码生成服务。
Coze 仅是应用运行时依赖；除非 Issue 明确涉及 AI 接口，否则不要触碰 Coze 集成。
保留用户和其他开发者已有修改，不做 Issue 外重构。
不得输出、读取或提交密钥与真实学生数据。
完成前运行相关验证，检查 git diff，并报告未验证边界。
```

## 1. 新会话初始化提示词

适合三人每天开始新任务时使用。

```text
你正在海豚云仓库中工作，我的角色是【开发者 A / 开发者 B / 质量构建负责人 C】。

当前任务：GitHub Issue #<编号>《<标题>》
当前分支：<分支名>
Issue 内容与验收标准：
<粘贴 Issue 或提供可读取链接>

先执行只读检查：
1. 完整阅读 AGENTS.md，以及 Issue 引用的 docs 文档。
2. 检查 git status、当前分支、最近提交和相关文件。
3. 找出现有实现、调用关系、测试和可能的跨模块影响。
4. 用简短计划列出要修改的文件、验证方式和风险。

边界：
- 只处理这个 Issue，不顺便重构无关代码。
- 开发过程禁止调用 Coze、Coze CLI 或外部代码生成服务。
- 暂不 commit、push、merge、tag 或发布，除非我之后明确授权。
- 如果验收标准与现有文档、接口、权限或数据不变量冲突，先指出证据并暂停会改变方向的实现。

检查完成后直接开始可以安全确定的实现，并持续报告关键进展。
```

```text
<逐条粘贴 Given/When/Then>

- apps/client/app/<范围>
- apps/client/src/features/<范围>
- apps/client/src/shared/<范围>
- packages/ui、packages/auth、packages/api-client 中与本 Issue 直接相关文件

需要先协调、不要自行改变：
- supabase/migrations 和公共数据库契约由开发者 B 主持

- UI 变化生成可供 PR 使用的截图说明。
- 最后检查 git diff，报告修改、命令结果、风险和未验证平台。

不要自动 commit 或 push。
```

## 3. 开发者 B：服务端与治理功能提示词

```text
我是海豚云开发者 B。请实现 Issue #<编号>：<学生分 / 班级分 / 银行 / 罚款 / 撤销 / AI 网关功能>。

目标与验收：
<粘贴目标和验收标准>

允许修改：
- apps/client/src/features/<本 Issue 业务域>
- supabase/functions/<本 Issue 范围>
- supabase/migrations 新增迁移，不修改已合并迁移
- supabase/tests/<本 Issue 范围>
- packages/domain、validation、api-client 中直接相关契约
- 对应文档与测试

实现前必须确认：
- 角色授权范围和 RLS 策略。
- 是否需要事务、行锁、幂等键、operation_id 和审计。
- 撤销时原记录如何保留、反向记录如何关联。
- API 变化是否会影响开发者 A 正在使用的 DTO。

硬性不变量：
- 学生分、班级分、海豚币、成绩不得混用字段或互相自动换算。
- 海豚币余额不得为负；余额和流水必须在同一事务提交。
- 不信任客户端提供的 actor、role 和作用范围。
- 分值和币账流水不可变；撤销新增反向记录。
- 相同幂等键不得重复产生业务结果。
- 开发过程禁止调用 Coze 或 Coze CLI。
- 若涉及 Coze，只实现海豚云运行时网关或 Skill API；Coze 不能直连数据库或执行未确认写操作。

验证：
- lint、typecheck、单元测试。
- 本地迁移从空库执行。
- RLS 正向与反向角色测试。
- 幂等、并发、余额不足和重复撤销测试。
- 检查 git diff 和迁移回退说明。

最后输出变更摘要、验证证据、API／迁移影响、风险和未验证边界。不要自动 commit 或 push。
```

## 5. 数据库迁移与 RLS 提示词

```text
请针对 Issue #<编号>实现数据库迁移和 RLS。

当前实体与关系：<粘贴或引用文档>
角色矩阵：<粘贴相关权限>
验收标准：<粘贴>

要求：
1. 只新增一个命名为 YYYYMMDDHHMM_<issue>_<description>.sql 的迁移；不编辑已合并迁移。
2. 使用 UUID、UTC timestamptz、必要外键、唯一约束和索引。
3. 明确 SELECT/INSERT/UPDATE/DELETE 策略；不可变流水禁止 UPDATE/DELETE。
4. 不信任客户端 actor_id 和 role，使用 auth.uid() 及授权关系。
5. 为每条策略写正向和越权测试。
6. 涉及余额、撤销或幂等时使用原子函数、事务约束和并发测试。
7. 写出前向迁移、兼容性和回退方案；若回退会丢数据必须明确说明。

请先检查现有 Schema 和迁移顺序，避免重复表、策略或索引。开发过程禁止调用 Coze 或 Coze CLI。执行空库迁移和数据库测试，最后报告结果，不要自动 commit 或 push。
```

## 6. 质量负责人 C：代码 Review 提示词

```text
我是海豚云质量与构建负责人 C。请 Review PR #<编号>，当前只做只读审查和验证，不修改代码。

请先阅读：
- AGENTS.md
- 关联 Issue 和验收标准
- PR 描述、diff、相关文档与测试

审查优先级：
1. P0：越权、密钥泄露、余额错误、数据损坏、错误迁移。
2. P1：核心流程失败、幂等失效、并发撤销、Coze 故障拖垮普通功能。
3. 验收标准、错误处理、跨端行为和回归。
4. 测试质量、可维护性和无关改动。

涉及业务时重点检查：
- 学生分、班级分、海豚币和成绩是否独立。
- RLS 是否使用真实登录身份而非客户端角色。
- 币账是否原子、余额是否可能为负。
- 撤销是否新增反向记录并防止重复。
- 班级端是否泄露成绩、余额或罚款。
- AI 写操作是否只生成草稿、确认后由海豚云服务执行。
- 开发代码中不得存在 Coze CLI 或外部生成痕迹；Coze 只限运行时 API。

运行 PR 相关的 lint、typecheck、测试和最短角色路径。不要因为 CI 绿就默认正确。

输出格式：
- Findings：按 P0/P1/P2 排序；每条包含文件与行、问题、触发条件、影响和修复方向。
- Questions：确实需要作者回答的项目。
- Verification：实际执行命令、commit SHA 和结果。
- Verdict：Approve / Request changes / Blocked，并说明未验证边界。

如果没有可操作问题，明确写“未发现阻止合并的问题”，同时说明剩余风险。不要修改、commit、push 或合并。
```

## 10. Coze 运行时接入提示词

仅开发者 B 在对应 Issue 中使用。本提示词不会调用 Coze 生成代码，而是让 Codex在本地仓库实现运行时适配。

```text
请在海豚云本地代码中实现 Issue #<编号> 的 Coze 运行时接入。开发过程严禁调用 Coze CLI、Coze Code 或任何外部代码生成能力；只允许根据仓库契约编写并测试海豚云自己的适配代码。

目标：<只读查询 / 写操作草稿 / 降级>
允许的 Skill：<白名单>
角色范围：<矩阵>

安全要求：
- Coze token 和 Skill secret 只存在服务端环境。
- Coze 不接收 Supabase service role key 或用户 JWT。
- 使用短期、单用途、绑定用户和工具白名单的上下文 token。
- Coze 只返回文本、白名单卡片或 action draft。
- 写操作不得由 Coze 直接执行；客户端确认后由海豚云服务重新授权、检查版本并幂等执行。
- 无效结构、超时、限流和服务故障统一降级，不影响普通业务。
- 日志脱敏并保留 request_id，不记录完整隐私内容。

测试：
- mock Coze 正常、超时、无效 JSON、越权工具、重复响应。
- 草稿过期、重复确认、权限变化和数据版本变化。
- Coze 完全关闭时普通业务回归。

不要在测试中调用真实 Coze，除非 Issue 明确要求在隔离 staging 做运行时联调且我另行提供授权。不要 commit 或 push。
```

## 16. 提示词反例

不要使用：

```text
帮我把海豚云做完。
看看代码有没有问题并修好。
把所有测试都跑一下然后发布。
```

这些提示缺少 Issue、范围、验收、权限和验证边界，容易造成跨模块修改、误提交或假完成。应使用前面的模板，把任务缩小到可在一个 PR 内完成。
